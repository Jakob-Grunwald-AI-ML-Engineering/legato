## Runtime integration details

The public path is `YAMLConfig.load(from:)`, `Tokenizer(modelPath:template:debugLevel:)`, `ModelLoader.loadModel(from:configuration:)`, then `InferenceManager.generateResponse`. The last returns generated token IDs, prefill duration and stop reason. Generation creates fresh KV state per request. Forward every YAML option to the manager: context, batch, split head, version, in-model argmax, sliding window, update-mask prefill, dynamic prefill slicing, prefix, vocabulary and head chunk sizes. The [model loader](https://github.com/Anemll/Anemll/blob/f4ad26d061dc2e426faa19f81c367343bdeb9f0d/anemll-swift-cli/Sources/AnemllCore/ModelLoader.swift) loads compiled infer/prefill functions and Gemma rotation functions separately.

Qwen 1.7B metadata specifies context 2048, batch 64, two LUT6 transformer chunks, FP16 embeddings, LUT6 head and 16-way head splitting. Gemma metadata specifies context 4096, batch 64, one chunk, LUT8 embeddings, LUT6 head, vocabulary 262144, 16 head chunks of 16384, in-model argmax and sliding window 512. Both enable dynamic prefill slicing. Preserve their complete compiled directories beside meta.yaml, tokenizer files and config.json; flattening weights loses required files.

For background requests use `.cpuAndNeuralEngine` and debugLevel 0, and audit the whole execution loop for explicit GPU work. The [inference source](https://github.com/Anemll/Anemll/blob/f4ad26d061dc2e426faa19f81c367343bdeb9f0d/anemll-swift-cli/Sources/AnemllCore/InferenceManager.swift) contains a MetalArgmax path enabled for some monolithic debug configurations. CPU_AND_NE still permits CPU fallback. Its mutable unchecked-Sendable manager needs serialized ownership; cancellation must not race its fields or unload a model while a prediction remains in flight.

ANEMLL's tokenizer wrapper does not expose `enable_thinking`. Its app's `/no_think` instruction is insufficient to claim the hard template switch. The pinned [Qwen template](https://huggingface.co/Qwen/Qwen3-0.6B/blob/c1899de289a04d12100db370d81485cdf75e47ca/tokenizer_config.json) renders an empty thinking block after the assistant header when thinking is disabled. Verify actual input token IDs against that form. Gemma has different supported roles; preserve the same semantic cleanup instructions in its supported user-turn template, avoiding ANEMLL's fallback that maps a system message to a model turn.

## Background execution limits

Apple's [WWDC25 background execution session](https://developer.apple.com/videos/play/wwdc2025/227/) introduces iOS 26 continued-processing tasks for explicit user-initiated work, with progress, expiration handling and completion signaling. Scheduling remains managed and background priority may differ. It also describes supported-device background GPU access with a capability and runtime resource check. Therefore “iOS never permits GPU work in the background” is too broad; the existing keyboard or intent path may still lack that access.

Apple's [Background Inference entitlement](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.developer.background-tasks.continued-processing.inference) is iOS 27+ and applies to background Neural Engine access there. It is not an iOS 26 entitlement requirement. Neither this API availability nor existing speech-model behavior establishes that this stateful LLM will finish through Legato's keyboard/Action Button flow. The accepted shared-source trial supplies bounded recording/cleanup/delivery feasibility after warmup, with lifecycle recorded; it does not establish physical ANE dispatch or a separate trigger-specific performance matrix. Cold background model initialization is outside the accepted scope.

Measure release-mode timings without an attached debugger, and capture Instruments attribution in separate runs. Keep process-cold, model-cold and loaded-weights/fresh-KV definitions separate. Preserve failures, expiration, cancellation, fallback, prompt-infeasible cells and missing external diagnostics. Do not count a fallback's successful final text as an ANE success. Foundation Models and the existing String-only MLX adapter do not supply all phase/token metrics through that interface; report unavailable metrics as N/A instead of deriving token counts from text length.

## Own-pipeline effort, risks and flexibility

These are engineering estimates, assuming one engineer familiar with Core ML/PyTorch, an available Mac/iPhone and adequate storage. They are not measured project durations. A pinned ANEMLL harness and artifact wiring are days; an independent Qwen-only pipeline with trained-weight loading, stateful prefill/decode, Swift tokenizer/generation and export parity is roughly 1–2 weeks; robust quantization, multiple architectures and release maintenance are several weeks. The synthetic layer settles a narrow operator/state feasibility question and has already exposed numerical work remaining.

A standalone pipeline must own RMSNorm/QK normalization, RoPE/GQA, ANE-friendly tensor layouts and split attention, approximately 1 GB or smaller weight chunks, state ownership, prefill/decode transitions, tokenizer/chat-template parity, model packaging and Swift cancellation. Core ML's chosen hardware placement must be inspected per shape and device. LUT palettization and 4-bit formats are not interchangeable guarantees of ANE acceleration; validate supported layouts, reconstruction error and cleanup quality. BF16-trained activations can overflow FP16 even if individual weights fit; test residual ranges, scaling transformations and long/context-boundary runs rather than relying on export success. ANEMLL's [Qwen converter](https://github.com/Anemll/Anemll/blob/f4ad26d061dc2e426faa19f81c367343bdeb9f0d/anemll/ane_converter/qwen_converter.py) and [FP16 handling](https://github.com/Anemll/Anemll/blob/f4ad26d061dc2e426faa19f81c367343bdeb9f0d/docs/FP16_SCALING.md) provide reference implementation choices, not a portable proof for new models.
