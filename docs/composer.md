# Composer offshoot

Composer is a developer spike on `epic/composer` (#108), separate from `main` and `live`. One composition creates one Room, a mutable document, one writing conversation and a session log; recording can pause and resume within that composition. Soniox supplies speech to two decoupled stages: fixed-Haiku local sentence cleanup, then the selected document writer. Only validated sentences reach the writer. Pause and Insert drain pending work without buying an additional polishing request. There is no on-device transcription fallback.

## Architecture

`LegatoComposerDoc` is Foundation-only. Its lines have stable IDs, a kind (`p`, `li`, `oli`, `h1`–`h3`, `quote`), a version and identified words. Words carry optional confidence, language, alternatives and a pinned flag. Only validated dictation is appended to document lines and their append-only accepted transcript; original ASR words and immutable source IDs remain in the private Room log. The document writer revises through versioned operations. Word diffs preserve surviving IDs and confidence; newly written words have no ASR confidence. Edits check only the versions of touched lines. Replacing a pinned word fails; Undo fails if the affected lines changed afterward. Transactions contain `txnId`, `origin`, `ops`, `inverse`, `groupID`, revision and animation hunks.

`LegatoRoom.Room` is the host actor that orders envelopes and applies document mutations. Only publications minted by `ComposerDocument` can enter `doc.*`; arbitrary `publish` calls to those channels fail. Subscribers receive independent streams: UI defaults to newest-only, other participants to unbounded. The host session explicitly uses an unbounded UI stream to process all transactions before publishing keyboard values.

| Channel | Contents |
| --- | --- |
| `asr.tail` | Uncommitted display text; never agent input. |
| `asr.segment` | Final words and segment timing/boundary metadata. |
| `user.intent`, `hint` | Mode changes, taps, picks and bound spoken corrections. |
| `correction.draft` | Captured correction preview and host countdown timestamps; not writer context. |
| `doc.ops`, `doc.snapshot` | Applied transaction and resulting document. |
| `sentence.cleanup` | Private cleanup queue/request/result/provenance diagnostics; never writer input. |
| `sentence.validated` | Validated-unit identity/order and continuation metadata for the writer. |
| `agent.status` | Busy state, pending targets and document-writer diagnostics. |
| `alternatives` | Candidate alternatives. |
| `session` | Lifecycle, transcription status and errors. |

`ComposerSession` in `LegatoAppServices` owns the microphone, Room, Soniox client, ordered sentence-cleanup pipeline, document writer, alternatives and hint binder. Its intercepted segment routing lets the binder consume a short correction instead of appending it as content. The host uses a resumable lifecycle: `listening → trailing → finalPass → paused → listening`. Pause drains transcription, sentence cleanup, validated handoffs and already-triggered writing work; it does not start another automatic final or quiet polishing request. Record resumes the retained document, mode, conversation and correction services with a fresh Soniox connection. Default non-resumable Rooms still finish at `done`. Insert waits for the same pending pipeline work before capturing processed text; successful acknowledged delivery ends and clears the composition. Failed delivery retains the paused draft and conversation. If the draft changes during delivery, the newer draft is preserved with a visible notice. The main Cancel/X ends the session and clears the composition, selection and captured correction without insertion; the correction popup X only discards its instruction. Session logs are retained.

After acknowledged Insert, the host retains a volatile compact topic reference for the current app run: up to 1,600 characters of the last delivered draft and 400 characters of recent explicit writing requests, with paragraph/word-boundary truncation and an omission flag. This is deterministic text compaction, not a model-generated summary. A new writer receives it as read-only background, separate from current content and instructions; prior requests never authorize app actions or append themselves to an empty draft. No tool calls, results, room events or IDs are carried over. The reference is not restored from disk and is omitted from diagnostic request copies; existing session artifacts retain their existing behavior. Main X or `clear_composer` clears only the current draft; **New topic** in each mode menu clears both draft and topic context. Pause retains the full current working conversation unchanged. No extra model request is made for compaction.

## History and recovery

Each composition owns one History entry (the Room UUID, engine `composer`), upserted atomically through the shared store with its first-stored date kept; unrelated and unreadable JSONL rows survive. Identical text is never rewritten. Accepted snapshots, Pause and background checkpoint in order; an empty reset never overwrites the last nonempty text. Clear, Cancel, New topic and Insert first flush the checkpoint and refuse to proceed (draft kept, visible error) when storage fails; a later successful write of the same composition clears only that error. Insert rotates the ID, so continuing after Insert is a new composition. Repeated upserts do not teach the vocabulary. `ComposerSession.historyRevision` advances after each successful write or import; the iOS History tab and the Mac menu list reload on it.

On first launch of a build with this feature, `ComposerHistoryBackfill` imports at most the 50 newest finished `sessions/<UUID>/` directories once (a marker file stops reruns, so deleted rows stay deleted). A session qualifies only if its log head records `input.source == microphone.soniox`, its log tail holds the `done` event (`final.md` alone also exists for paused sessions) and `final.md` has text; current, existing, debug and unknown-source sessions are skipped. Recovered rows use engine `composer.recovered`.

Insert attempts log `insert.requested`, `insert.acknowledged` or `insert.undelivered` on the `session` channel with the caller (`keyboard.button`, `host.instruction`, `mac.panel.button`, `mac.panel.shortcut`, `debug.bridge`), the character count and acknowledgement kind. On the phone the acknowledgement is the keyboard's `finalApplied`, meaning UIKit proxy operations ran; it does not confirm visible text in the target app.

## Speech, agents and corrections

`LegatoSoniox` connects to `wss://stt-rt.soniox.com/transcribe-websocket` with bearer authentication, model `stt-rt-v5`, mono 16 kHz PCM16, German/English hints, language identification and endpoint detection. Context includes up to 100 vocabulary terms plus a bounded mode/personal-prompt summary. Final subword tokens merge into words using their minimum confidence. Segments close on an endpoint, final punctuation, a gap of 0.7 s, 25 words or 8 s. The grey tail also includes finalized words awaiting a segment boundary. Stop sends `finalize`, waits for `<fin>`, sends an empty frame and waits for `finished`; idle transport sends keepalive after 10 s without audio.

`HintBinder` routes timed Dictation, Instructions and quote corrections before cleanup. Dictation accumulates across acoustic gaps/endpoints and the provider's 25-word/8-second transport chunks until sentence punctuation. Explicit finalize/Stop or an input-channel boundary flushes an unfinished fragment; a 120-word/30-second safety bound permits progress on very long speech. A following unit is marked as a continuation, not a paragraph command. Pending speech remains in the UI-only tail. Quote/Instructions quiet timers retain their existing independent behavior.

`OrderedSentencePipeline` runs at most two independent fixed-Haiku copyediting requests, with a 32-unit retained queue and backpressure. Each uses strict `submit_sentence` output and immutable sentence ID/sequence validation, with no document tools or shared writer conversation. Ordered binder admission appends each validated result once; late/canceled results cannot overwrite author edits. Unchanged words retain IDs/acoustic metadata; changed words get new IDs without invented confidence. Failures keep raw speech pending and show one explicit microphone retry; there is no raw fallback. Clear/New topic/Insert completion retires the pipeline generation.

`LegatoAgent.AgentRunner` is the sole document writer, with one active writing request and retained conversation. Validated sentences admit full captured-scope turns immediately; explicit Instructions and targeted corrections bypass sentence cleanup. Acoustic alternatives and raw provenance are removed from all writer events/history/reseeds, and session diagnostics never enter model context. Raw partials are activity/UI data only. Production validated-input sessions do not launch redundant quiet maintenance or final-polish requests. Existing legacy nonvalidated Room/runner callers retain their historical quick/quiet/final policy. Writer defaults are conservative: formatting and real errors first, minimal wording improvements only with an obvious quality gain, and substantial rewriting only for a current explicit request. A nice-prompt instruction can still transform the draft and consumes its directive.

Prompt layers are bundled base → mode (Auto, Message, Email, Prompt, Note) → personal prompt → vocabulary. Auto loads existing specialized guidance through `load_writing_guidance` while staying in Auto. The current quick/sentence/targeted/pause/final instruction is appended to the user turn, keeping the phase-independent system/tool catalog stable. The conversation requests ephemeral caching and reseeds beyond 50,000 input/cache tokens or five minutes idle. The existing `composer.liveModel` preference selects the document-writing model; the independent sentence copyeditor stays on Haiku without another switch or key. Its its saved choice is preserved, with Haiku as the unset default. Haiku disables thinking, Sonnet uses `between_tools` with low effort, and Opus uses `adaptive` with low effort. All document-writing phases use that same selection.

Tools are `view`, `replace_lines`, `insert_lines`, `delete_lines`, `replace_in_line`, `move_lines`, `set_kind`, `set_mode`, `request_compose` and `note`; Auto replaces `set_mode` with `load_writing_guidance`. There is no agent-delegation tool. Ordinary quick turns defer broad line replacement/insertion/deletion, moving and kind changes until a sentence, quiet-pause or final turn; targeted corrections can use them immediately. A deferral explicitly says to wait, instead of asking the model to refresh/retry. Schemas remain strict, with automatic tool choice and eager input streaming. The wire `versions` value is an array such as `[{"line":"L…","version":3}]`; the document API uses a dictionary internally. Genuine stale versions, unknown IDs, ambiguous replacements or pinned-word changes require a fresh view before retrying. Presented lines look like `L… v3 [li] text`, with confidence markup such as `⟨word|0.42⟩` stripped from edits.

Words below 0.6 confidence receive up to three ranked alternatives from vocabulary, platform spellchecking and learned correction pairs with bigram scoring. Tint is neutral from 0.9 upward. A pick directly replaces and pins the word. Tapping a word or selecting a quote captures subsequent speech as a correction draft instead of general dictation. The popup previews that draft; after 500 ms of quiet the host starts a one-second autosend countdown, interrupted by new speech. The wand sends immediately, with transcription drained at the existing boundary before the structured quote-targeted hint reaches the writer. Popup X discards captured and still-in-flight correction speech without editing the document. Choices feed `VocabularyLearner`; repeated agent corrections can promote pairs for later sessions. See [targeted correction and native evidence](uat/composer-quote-correction.md).

## Surfaces and setup

`LegatoComposerUI` is shared SwiftUI code for the keyboard and Mac panel, without `LegatoCore`. Stable line IDs animate moves; Pow supplies line disappearance, and line insertion/replacement uses blur/opacity. One `WordFX` clock per line caps blurred runs at twelve. Pow 1.0.5 is vendored at its pinned upstream revision with explicit `CGFloat` constants and typed rotation expressions for Swift 6.2 compatibility (see `Vendor/Pow/UPSTREAM.md`). Pending streamed tool targets highlight lines. The shared `WordFX` TextRenderer reports measured glyph bounds for hit testing, highlights and popup anchors; pinned words are underlined. A tap selects one word; deliberate native iOS press-and-slide or Mac press-and-drag selects a quote through the same range contract. Popup placement avoids the full visible marked extent, points to the first or last selected glyph row, and reserves text-free space when neither side fits. See [native quote selection and popup evidence](uat/composer-quote-correction.md). Performance on the real animated keyboard remains an acceptance check.

On iOS, the composer pane uses two remembered Medium/Full heights above the compact action strip, with native keyboard colors and no QWERTY grid. Height changes happen on release; smooth animation remains unresolved ([motion report](uat/composer-height-motion.md)). `link.composer` carries a full snapshot and accumulated hunks since the acknowledged revision at a minimum 0.1 s publish interval. History retains 100 revisions; a gap requests snapshot recovery. Per-intent keys `link.composer.intent.<uuid>` carry timestamped actions. A composer lease keeps host heartbeats alive. Insert sends a session-bound request to the host, which finishes authoring and reuses the acknowledged keyboard insertion path; the extension calls `textDocumentProxy.insertText`. A changed target document or failed delivery leaves the composition available to retry. The extension receives values and sends intents; provider connections and keys remain in the host app.

### Keyboard session

`KeyboardSession` (host) follows `link.presence`, which now carries the surface on screen (`typing` or `composer`). Appearing opens a session: it holds one microphone stream for the whole appearance (only when a lease already exists; otherwise the hop path applies), holds an authenticated, upgraded Soniox connection for the surface without its start request (unbilled), sends a credential-free HEAD to the Messages API to warm the shared connection, and on the composer surface builds the composition (cleanup pipeline and writer). Disappearing, or presence going stale, ends the composition (History keeps it), the writer conversation, cleanup and dictation context and the delivered-topic reference, and releases the stream. Insert and further speech within one appearance stay one composition.

The surface is the mode; there is no Dictation/Instructions toggle. `AudioGate` routes chunks: `idle` discards them, `agent` feeds the composition, `dictation` feeds a separate Room whose finalized segment lines go to a `DictationRouteSink` and never reach the composition. A mic tap only opens the gate: it sends the start request on the held connection and audio follows on the same socket without waiting (Soniox has no start acknowledgement). Tapping again sends 200 ms of silence and `finalize` on either route; the composition keeps listening, the finalized stream ends in the background after `<fin>`, and a fresh held connection waits for the next tap. Insert drains the composition to paused first. Switching surfaces abandons the open route: the provider's unfinished words are dropped (`SonioxClient.close`), already-final agent words drain into the composition, and the microphone keeps running. Held connections fail quietly (`asr.dropped`) and reconnect in the background with backoff; a missing or rejected key stops retrying until the next tap reports it. Soniox bills a started stream for its whole duration, idle included, and ends it with 408 after 20 s without audio or keepalive; a held connection has no deadline for its start request but closes with 1001 after 40 s without a keepalive, and counts against the connection limit ([WebSocket authentication](https://soniox.com/docs/guides/websocket-authentication#connection-timeouts)). The client sends keepalive after 10 s.

### Dictation into the field (ABC)

On the typing surface each finalized line goes through `DictationPipeline` (host) to a cleanup-only Haiku call: `SentenceCleanupClient` with the `dictation-cleanup.md` prompt (punctuation, casing, fillers, obvious ASR fixes with vocabulary, spoken "new line"/punctuation; never rephrasing, answering or adding). At most two calls run at once (`DictationCleanupPipeline`) and lines are delivered in speaking order. A failed call, a result `DictationCleanupGuard` rejects, or one slower than 2.5 s inserts the raw line. Context is the previous two lines (cleaned text once known, raw before) plus the text before the cursor (`link.presence.contextBefore`, never from a secure field), reset when the keyboard session closes. The prompt (about 650 tokens) is above Haiku 5.5's 512-token cache minimum, so its system block carries `cache_control` and the tool schema is identical for every line; opening the dictation surface warms it with one tiny request (at most once per 4 minutes).

`link.dictation` carries `{sessionID, lines: [{lineID, seq, raw, text, status}]}` (`status` is `cleaned` or `raw`; `text` is what to type). The keyboard types the lines with `DictationTypist` (`TypewriterDrain` pace, separator and sentence capital judged at the cursor when each line starts) and writes `link.dictation.ack {sessionID, upTo}` as each line finishes; the host drops acknowledged lines, so a republished or restarted keyboard never types a line twice. A key, completion or cursor pan, or a context that is not the echo of the typist's own inserts (`OwnEditEcho`, 250 ms to settle), drops the rest of the current line; later lines go in at the new cursor. The ABC surface is the pre-offshoot keyboard (`KeyboardHeights.height`, 297 pt portrait): word row (live tail while dictating), tool row (undo, redo, composer key, mic) and the native grid.

Each tap records mic tap → first live tail (`probe.tap.tail`: route, warm, idle seconds, tap→gate, tap→first routed audio, tap→tail) in the host log, the composition's session log and `composer-state` under `keyboardSession.probes`. Internal `keyboard-tap` taps the gate on the current surface.

On Mac, the hotkey starts/stops the same host session (Right Command by default, with tap-to-latch and hold-to-talk behavior). Opening the nonactivating `NSPanel` preserves the captured editor; clicking it enables panel-scoped keyboard shortcuts while retaining the insertion target. The panel chooses the target application's screen and appears below its notch, or top-centre on a display without one. Its action strip contains mode, Undo, disabled Redo, paper-plane Insert, Cancel, Mute and Record/Pause, with visible shortcuts. Insert waits for final authored text, then uses the captured `FieldWriter` target with paste fallback. Verified insertion clears the composer; clipboard-only fallback retains it and displays a notice.

Enter Claude and Soniox keys in each platform's Settings; they are local Keychain entries (`de.gruenwald.legato.claude` and `de.gruenwald.legato.soniox`, account `api-key`). Settings provide one writing-model selector and a personal prompt. The iOS companion has Compose/History/Settings tabs and a Settings-only system-keyboard gate for ordinary text entry. Its provider editors never display saved keys; each saves only its own nonblank replacement, preserving the other key. Mac Settings uses Overview, Writing, API Keys and Shortcut sidebar pages, with actual permission status in Overview and blank entries preserving saved keys. See [physical iOS settings checks](uat/composer-ios-companion.md) and [Mac settings checks](uat/composer-mac-settings.md). Preferences use `composer.liveModel`, `composer.personalPrompt` and `composer.mode`; old restructure-model preferences are no longer used. Logs have no enable/disable setting. Missing keys produce a visible error and retain the session log.

## Reading and pulling sessions

The host writes `sessions/<UUID>/` beneath its Documents directory:

- `room.jsonl`: one JSON envelope per line, ordered by host `seq`.
- `final.md`: the last document's plain line text at each completed pause, Insert or Cancel; line-kind formatting applied by a surface is not included.
- `audio.m4a`: mono 16 kHz AAC from the first microphone take; `audio-2.m4a` and subsequent numbered files retain resumed takes. These contain the same microphone chunks forwarded to Soniox. A session failing before capture can have no audio file.

Each envelope has `seq`, `id`, `channel`, `participant`, `tMono`, `tOrigin`, optional `baseRev`/`causedBy`, and `payload`. `tMono` is host system uptime at publication, not a wall-clock date. `tOrigin` preserves origin timing; follow `causedBy` to connect a segment, hint or transaction. `baseRev` identifies the document revision attached to a publication.

Sentence diagnostics include immutable queued/validated IDs, `sentence.request`, `sentence.response` duration, pending/in-flight counts and visible failures on `sentence.cleanup`; source linkage never enters writer context. Document-writer diagnostics include `turn.phase` (`quick`, `sentence`, `targeted`, `pause`, `final`) and `turn.cancel` with its phase and are `agent.status` envelopes distinguished by `payload.event`: `conversation.seed` records system prompt and tools; `request` records a full-request SHA-256 hash and the latest appended message; `response.delta` preserves each SSE event type and data string; `ttft` records seconds to the first SSE event; `usage` contains merged provider counters including cache tokens; `tool.result` contains the result and `is_error`. `pending.edit` names targets before application; `error` records failures. TTFT here includes any first provider SSE event, so it does not necessarily mean first visible text or first complete tool input.

For an internal iPhone build, pull one session or all sessions with the device harness:

```bash
bash scripts/device/ctl.sh --target device pull-sessions Documents/sessions
bash scripts/device/ctl.sh --target device pull-sessions "Documents/sessions/<UUID>"
```

`pull-sessions` is an alias of `pull`, requiring a container-relative path; files land in the target-specific `$LEGATO_STATE` scratch tree under `pulled/`. Keep the same target, bundle identity and device environment between commands. For Mac, set `LEGATO_MAC_DATA_ROOT` to the host's actual Documents directory and pull relative to that root:

```bash
LEGATO_MAC_DATA_ROOT="$HOME/Documents" bash scripts/device/ctl.sh --target mac pull-sessions "sessions/<UUID>"
```

Check the app's actual Documents location if sandbox/container configuration differs. See [the harness guide](../scripts/device/README.md) for transport and root overrides. Inspect a copied session locally:

```bash
jq -c 'select(.channel == "session") | {seq, tMono, payload}' room.jsonl
jq -c 'select(.channel == "agent.status") | {seq, participant, payload}' room.jsonl
jq -c 'select(.channel == "doc.ops") | {seq, causedBy, payload}' room.jsonl
```

Read audio and segment events alongside document edits before judging lost content or correction quality. Compare cache counters and cold/warm TTFT separately. `SessionLog` redacts supplied secrets, sensitive field names and bearer/key patterns; this does not remove spoken personal content, prompts or audio. Logs are detailed session artifacts.

Internal `composer-debug-seed <text>` prepares a paused local draft without starting providers, reading credentials or capturing a microphone. It supports native insertion and clear-flow acceptance only; it does not establish speech or model quality.

## Acceptance still pending

Package implementation and compiled apps establish different evidence from real speech acceptance. Real provider, device and native microphone evidence is recorded in [the phone report](uat/composer-phone.md), [Mac report](uat/composer-mac.md), and [native voice report](uat/composer-native-voice.md). Current one-writer validation is recorded in [the single-writer report](uat/composer-single-writer.md). Joint review, sustained background behavior and performance acceptance remain distinct from these bounded checks. No threshold change is justified yet. Issue #118 remains open; merging this document does not complete its sessions, findings or epic checklist.

The [physical probe report](../spikes/composer-probe/README.md) establishes only requested keyboard layout heights of 600/1200/2000 pt on a 402×874 pt screen and idle available-memory samples around 156/148/137 MiB. It does not prove visible height/clipping, touch routing, animated memory headroom, blur FPS, host/keyboard RTT, Soniox quality, phone Claude timing or provider background survival. Harness/fixture success is separate from built-app and paid-provider proof.

Review the six real sessions for content retention, pinned corrections, mode behavior, Insert during an agent pass, stale-edit recovery, latency/cache use and microphone/provider shutdown. Record evidence before recommending changes to segmentation, confidence, alternatives or restructure thresholds. Extend existing findings where possible (#119–#124 are already reserved follow-ups); the return of this offshoot to `main` is a later decision.
