# Selected model resources

Legato prepares the selected speech and cleanup resources at foreground startup or first use and retains them across dictations and microphone expiry. Ending a microphone lease ends capture; it does not unload selected weights. The normal keyboard warmup and Action Button routing remain the entry points. There is no idle model-unload timer and preparation generates no dummy text.

Qwen3 1.7B (Core ML) is an explicit download in Cleanup settings. Its selected weights serve both foreground and background cleanup, Live passes and Refine. Legacy MLX background settings do not substitute Foundation Models or disable a selected Core ML model. Missing or unprepared Core ML resources report unavailable and preserve input; preparation errors are surfaced for retry. Apple Foundation Models remains an explicit choice and the zero-download default when no local model is selected. Existing selections are preserved. Core ML uses an automatic eight-second cleanup budget when no time limit was chosen, including through Auto; an explicitly stored limit is retained. Other backend defaults remain four seconds.

The selected resource owner coalesces preparation and checks selection generations before publishing readiness. A canceled admission returns promptly without canceling the shared model load or starting capture later; the next admission can join that preparation. A model switch or memory-pressure event revokes readiness, joins outstanding preparation and relinquishes resource ownership. The next foreground preparation restores it. Stop bypasses model preparation. Resource preparation does not reset an active speech decoder, transcript stream or callback. Meeting maintenance preserves selected speech weights even when its own recent-model cache evicts them.

Selected FluidAudio resources are pinned independently of incidental meeting models. MLX retains its model container and releases cache ownership without claiming that cancellation joined opaque native generation. Apple Speech requests `SpeechAnalyzer.Options.ModelRetention.processLifetime` and creates fresh per-run analyzers; the Speech framework owns its resource cache. Foundation Models retains a prewarm-only session and creates fresh sessions for actual responses. Its prewarm API does not guarantee physical residency. Process termination and OS memory decisions remain outside application control.

The Core ML installer downloads only a shipped manifest of 25 files from `anemll/anemll-Qwen-Qwen3-1.7B-ctx2048_0.3.5` at revision `0977a61d00e39118aab5ed1e510f1d228df5eefd`. It verifies sizes and SHA256 before publishing a receipt. State reads check the receipt and file stamps; initial runtime preparation verifies full hashes again. Incomplete, changed and symlinked artifacts cannot become ready. Weights are not bundled with the app. The pinned ANEMLL runtime is vendored with source provenance, cancellation fixes and bundled third-party notices; production has no dependency on the spike checkout or its caches.

Native Core ML ownership spans prediction settlement, including cancellation and release. Prompt rendering must match the checkpoint's canonical non-thinking chat template. Context overflow, incomplete generation, timeouts, stage failures and guard rejection preserve input through the existing production pipeline. Cleanup reports expose outcomes independently of whether the output changed, including outcomes from multiple Live passes. The existing numeric-value guard limitation is tracked in #54.

Core ML requests CPU and Neural Engine compute units in both app states. This is an allowed-compute configuration, not evidence of actual Neural Engine placement. The accepted spike's phone measurements do not establish sustained production energy use, initialization-versus-warm thermal behavior, or residency after process loss. Those measurements remain explicit validation work in #58. The broader reduction of development settings is tracked in #62.

[Native checkpoint evidence](../validation/58-native-coreml.json) records three short public fixtures on an Apple M1 Pro with 32 GB RAM. The Release production pipeline completed 3/3 with exact reference output, no timeout, failure or guard rejection, in 4.35–4.73 seconds under an actual eight-second deadline. Debug also passed 16 stage calls and three deadline calls. Each separate process required 119–122 seconds of preparation before generation. Thermal samples were nominal; energy, sustained heat, actual accelerator placement, iPhone behavior, ITN, microphone admission and keyboard delivery were not measured. These binaries precede the runtime module rename and the CoreMLModelStore cache-release race fix; the generation algorithm is unchanged, but final builds and lifecycle checks are separate evidence. Raw JSONL records and executable, harness and manifest digests were independently rechecked; source digests identify the earlier checkpoint.
