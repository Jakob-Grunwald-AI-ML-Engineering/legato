# Spike #3: macOS system audio and mic capture, with live speech recognition via FluidAudio

This is throwaway code under `spikes/mac-audio/`. It was verified on macOS 26.6.2 (25G83) on Apple Silicon, with Xcode 27.1.

## Verdict

**Feasible.** A Core Audio process tap captures system audio. Nemotron multilingual streaming transcribes mixed German and English with the language set to `auto`. The first text appears after about 1.8 s.

**The "me vs. them" split needs headphones or echo cancellation.** Without them, the mic picks up the speakers as well.

## What was built

A minimal Swift 6 SwiftUI app with bundle ID `de.gruenwald.legato.spike3`. The project is generated by XcodeGen from `project.yml`.

- **`Sources/AudioCapture.swift`** captures the two streams:
  - `SystemAudioTap`: a global stereo tap that excludes our own process. It uses `CATapDescription(stereoGlobalTapButExcludeProcesses:)` and `AudioHardwareCreateProcessTap`, plus a private aggregate device on the default output.
  - `MicCapture`: an `AVAudioEngine` input.

  Each stream has its own converter to 16 kHz mono Float32, and its own stats (RMS, peak, count of all-zero buffers).
- **`Sources/StreamTranscriber.swift`** runs one `StreamingNemotronMultilingualAsrManager` per stream, sharing one loaded model. A segment is committed after 1.2 s of silence.
- **`Sources/Session.swift` and `Sources/LegatoSpikeApp.swift`** show a "Me" column and a "Them" column and a language picker. They also provide a `--selftest` mode that writes `selftest.json` and WAV files.
- **`build.sh [adhoc]` and `selftest.sh [seconds] [lang]`.** The self-test launches the app through `open -W -n`, so that macOS asks the app for permission rather than the terminal.

Info.plist contains `NSMicrophoneUsageDescription` and `NSAudioCaptureUsageDescription`. The sandbox is off, the entitlement `device.audio-input` is set, and the hardened runtime is on.

### Choice of speech recognition model

FluidAudio is pinned to **exactly v0.17.7**.

- **Nemotron multilingual 0.6B** (`StreamingNemotronMultilingualAsrManager`) is truly streaming. It covers en, es, fr, it, pt, de, zh and ja, and offers an `auto` language setting. The spike uses the 1120 ms latency tier.
- **Parakeet v3/Ultra** (`SlidingWindowAsrManager`) is not live: its first text arrives after about 13 s. It stays useful as a more accurate second pass after a meeting.

## Minimum macOS

**macOS 14.2.** `AudioHardwareCreateProcessTap` is marked `API_AVAILABLE(macos(14.2))`. See https://developer.apple.com/documentation/CoreAudio/capturing-system-audio-with-core-audio-taps. Only macOS 26.6 was tested.

## Verified results

Command: `./selftest.sh 15 auto`, with `say -v Anna` (German) and `say -v Samantha` (English) looping through the speakers. The full output is in `selftest.json`.

- **Tap:** the "Them" stream had a peak of 0.87 and transcribed mixed German and English.
- **Silent buffers:** 195 of 1421 tap buffers were all zero. That was the silence before `say` started. So the zero-buffer counter cannot tell a missing permission from real silence.
- **Mic:** authorized, with no zero buffers. It also picked up the speakers, so the speech appears in both streams.
- **Latency** (two streams, Debug build):

  | Measure | Value |
  |---|---|
  | First text | 1.7–1.9 s |
  | Processing per chunk, mean | 330–440 ms |
  | Processing per chunk, max | 490–850 ms |

- **Cold start:** about 590 MB to download. The first model load took 201 s, spent compiling for the Neural Engine. Later loads took 19.7 s.

## Not verified

- **First-run permission prompts.** They were already granted on this Mac.
- **Team-signed build.** It needs the Program License Agreement accepted and a Mac Development certificate. The verified build was ad-hoc signed.
- **Real-world conditions:** a real call, a real voice, headphones, Bluetooth output, and macOS versions below 26.

## Manual checklist

1. Run `./build.sh` (or `./build.sh adhoc`), then open `build/Build/Products/Debug/LegatoSpike.app`.
2. Grant Microphone and System Audio Recording. If "Them" stays empty, enable the app under "System Audio Recording Only" and restart it.
3. Put on headphones and join a call or play a YouTube interview.
4. Speak mixed sentences, and try the `auto`, `de-DE` and `en-US` settings.
5. Note errors at language switches, punctuation, and how long a line takes to commit. Note any audio drops when switching output, for example from speakers to AirPods.

## Open risks

- **Silent zeros.** A permission denial and a missing `NSAudioCaptureUsageDescription` both look the same: the call succeeds, but every buffer is zero. https://dev.to/nickdelv/2000-buffers-of-nothing-3i8
- **Zeros mid-session.** On macOS 26.5 beta, buffers reportedly go silent for 53 s to 16 min, and only a full teardown recovers. A watchdog is needed: if the mic hears speech but the tap is zero for N seconds, rebuild the tap. https://developer.apple.com/forums/thread/825780
- **No public way to check the system-audio permission in advance.** AudioCap uses a private TCC call for this, which this spike avoids.
- **Echo.** The options are requiring headphones, echo cancellation (Apple's voice processing, or FluidAudio LocalVQE using the tap as reference), or removing duplicate text between "Me" and "Them".
- **Model licence.** The Hugging Face card says OpenMDW-1.1, not Apache-2.0. https://huggingface.co/FluidInference/Nemotron-3.5-ASR-Streaming-Multilingual-0.6b-CoreML
- **Accuracy.** The first German sentence came out as "das ist ein festes System Audios"; later repeats were correct. The 560 ms tier loses punctuation over long sessions (FluidAudio #687).
- **FluidAudio changes fast.** New versions come roughly weekly, so it stays pinned to an exact version and updates are deliberate.
